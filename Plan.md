## Находки первого запуска 1.31.0 на сервере (10.10, ночью)

**Что делали** (пользователь, сервер `analytics`): `git pull`, `./deploy.sh` (Enter на всех вопросах, кроме
`TOP_FREE_EVERY` — ввёл `7d`), затем `./backfill.sh UnityAssetsTools --dry-run`. Выложен 1.31.0 без ошибок; бот по-прежнему
не достаёт Bot API напрямую (программа ходит через прокси). Исходные материалы пользователь прислал файлами
`run-summary-20261010-012117.txt` (сводка репетиции) и `log.log` (терминал): они **вне git**, сводка — образец формата.
Пришёл ли файл сводки ботом — не подтверждено.

**Репетиция** (7 мин 20 с, лимит 40 страниц): прочитано 140 постов канала (#1770…#2054), 79 ссылок на ассеты, 60 постов-раздач
через бота — все 60 ассетов платные (взято 0, пропущено 60: путь с проверкой цены работает вживую). Из 58 обработанных
ассетов: 18 уже на аккаунте (страница не открывалась), 16 «добавились бы», **24 «Ошибка: Не удалось открыть … после
повторных попыток»**.

**Находка 1 — вкладка умирает и не восстанавливается.** 24 ошибки идут подряд после 16 удачных. В логе: «Навигация не
удалась … за 0ms: Object reference not set to an instance of an object» (47 раз — по две попытки `DOMContentLoaded`/`Load`
на ассет), один раз «Target closed … Connection failed to process Target.attachedToTarget. Timeout of 1000 ms exceeded»,
в конце «Не удалось пересохранить вход профиля: Session closed». Читается так: браузер или вкладка перестали отвечать,
а программа продолжает открывать ассеты в той же мёртвой вкладке. По коду это так и есть: вкладка создаётся один раз
(`Program.cs`, `browser.NewPageAsync()` ~632), `SafeGoToAsync` только повторяет `GoToAsync` на той же странице, цикла
восстановления нет. Мёртвые попытки засчитались в лимит 40 страниц, ошибочные ассеты нигде не запоминаются (следующий
прогон проверит их заново). **Причина смерти вкладки не установлена**: вероятно нехватка памяти (1 ядро, ~1 ГБ, общий
сервер), но доказательств нет — в разовом прогоне память не замеряется (`MemorySampler.Start()` только при `--watch`,
`Program.cs` ~397). На длинном прогоне (сотни ассетов) такая смерть превратит весь остаток в ошибки.

**Находка 2 — на сервере добавление в 2,5–3 раза медленнее, чем на Deck.** После репетиции `backfill.sh` вернул службу, и та
сразу сделала свой первый прогон: пять каналов, «взяли последние 50» (первое чтение двух новых каналов), настоящие
добавления. По присланному куску лога: проверка страницы в репетиции 13–28 с; настоящее добавление 35–59 с, в среднем
**~44 с на ассет** (на Deck в тот же день ~16 с). Время уходит на ожидание подтверждения «Accept» (15–30 с) и на появление
ассета в библиотеке (ещё 20–30 с). Расчёт при ~44 с на ассет: `UnityAssetsTools` (146) ≈ 1 ч 45 мин, `UnityAssetsNewFree`
(1114) ≈ 13–14 ч, остальные каналы (~220) ≈ 2,7 ч — всего около 18 ч. Чем закончился этот прогон службы — в присланном куске
не видно (оборван на ~25-м добавлении).

1. **Восстановление вкладки.** При `page.IsClosed` или нескольких `NavigationException` подряд создать новую вкладку (при

   прогон идёт дальше.
2. **Скорость добавления.** Сначала измерить, где уходит время (на сервере с `--verbose` на 3–5 ассетах). Варианты, можно
   сочетать: (а) не грузить лишнее — перехват запросов, блокировать картинки, шрифты, видео и аналитику (страница

   `userEntitlement: null`); (в) уменьшить ожидания (15–30 с на «Accept», 4 повтора по 2,5 с, пауза `--delay-ms`).
3. **Замер памяти в разовом прогоне** (не только при `--watch`), чтобы в сводке `backfill.sh` была строка «Память» и было
   видно, не нехватка ли её убивает вкладку.

## К чему стремимся

Все бесплатные ассеты Unity и ассеты, раздаваемые по промокоду со скидкой 100 %,
сами попадают на аккаунт(ы) Unity — без участия человека. **Деньги не списываются
никогда**: оплата нажимается только при итоге ровно 0.

Один репозиторий — несколько версий одной программы:

| Версия | Для чего | Состояние |
|---|---|---|
| Настольная: `run.bat` (Windows), `run.sh` (Linux, Steam Deck) | Человек запускает меню и выбирает источники | Работает |
| Сервер: Docker + `deploy.sh` | Сам раз в период читает новые посты каналов, бот пишет в Telegram; с 1.29.0 ещё и Fab (`FAB=on`) | **Работает на настоящем сервере с 19.09**: один аккаунт Unity, только Telegram-каналы, прогон раз в 6 ч; Fab — с 09.10 |
| Один `.exe` для компьютерного класса (10+ ПК, без установки .NET) | Школьный класс, каждому свой аккаунт | Позже |

### Где что запускается

- **Windows-ПК** (профиль `VR1-PC__betmansmall`) — основной ручной запуск, `run.bat`.
- **Steam Deck** — разработка, `run.sh`. Терминал VS Code здесь в Flatpak: экран только
  Wayland, `docker` нет, `podman` на хосте — через `flatpak-spawn --host`.
  Только здесь есть стенд `harness/` (в git не входит).
- **Сервер** — хост `analytics`, Ubuntu 20.04 (в контейнере Debian 12), Россия. Каталог
  `~/UnityAssetsDownloader`, запуск через `docker compose`. Телеграм-каналы оттуда открываются только через
  прокси (программа подбирает сам), Bot API — напрямую или по закреплённому адресу.
  Обновление: `cd ~/UnityAssetsDownloader && git pull && ./deploy.sh`. Окно для человека (Fab): порт
  `127.0.0.1:6085` на сервере, наружу не открыт; попасть — `ssh -L 127.0.0.1:6085:127.0.0.1:6085 <сервер>` и
  `http://127.0.0.1:6085/vnc.html?autoconnect=true&resize=scale` (именно `127.0.0.1`, не `localhost` — с
  `localhost` 09.10 было «Connection refused»), пароль — `FAB_VNC_PASSWORD` в `.env`.

### 4. ~~Проверка входа~~ — исправлено в 1.24.0, на сервере с 27.09 держится

**Что было.** За 19–27.09 в 9 прогонах из 37 сервер «входил заново», и почти каждый
прогон тратил 1,5–2 минуты на проверку входа (чтение каналов — 1–3 с).

**Причина — сама программа разлогинивала себя** (воспроизведено на Deck 27.09).
Браузер хранит cookies в папке профиля (`chrome/`) и обновляет их при каждом заходе
в магазин: cookie магазина `DS` живёт сутки и продлевается. А `session.dat`
сохранялся только при полном входе, но загружался в начале **каждого** прогона
поверх cookies браузера. Через сутки после входа программа подменяла свежий `DS`
просроченным, браузер его выбрасывал — и вход пропадал. На Deck: первый запуск —
«Сессия активна», второй через 3 минуты — «Сессия Unity истекла». Так же на сервере
27.09: `--check-login-page` в 05:13:32 «вы уже вошли», прогон в 05:13:48 загрузил
`session.dat` от 26.09 и «входа нет».

**Что сделано в 1.24.0:**

1. Из `session.dat` возвращается только то, чего в браузере нет (cookies сеанса —
   Chrome теряет их при закрытии), и только не просроченное (`CookiesToRestoreAsync`).
   В логе: «Загружено cookies из session state: 13 из 26».
2. После каждой успешной проверки входа и в конце прогона cookies пересохраняются —
   быстро, 11 мс: localStorage в отдельных вкладках снимается только после полного
   входа (`SaveSessionStateAsync(captureLocalStorage: false)`).
3. **Вход по требованию**: сначала читаются каналы, вход в Unity — только перед первым
   ассетом, который надо открыть в магазине. Новых постов нет — Chrome не ходит в
   магазин вовсе: «Проверять в магазине было нечего — вход в Unity не понадобился».
   Не вошли — ассеты не трогаются и место в каналах не запоминается.
4. Имя аккаунта при восстановленной сессии берётся из профиля, а не со страницы (−6…18 с).
5. Пустой прогон в режиме «только новые» больше не пишет предупреждение в `errors.log`.
6. `--verbose` показывает, чем cookies браузера отличаются от `session.dat`.

**Проверено на Deck вживую** (копия профиля, `--dry-run`, аккаунт не менялся):
три `--login` подряд — сессия жива каждый раз, расхождений нет, проверка 8,5 с;
прогон с ассетами — вход перед первой пачкой, 95 с на 48 ассетов; прогон без новых
постов — **13 с целиком**, из них 8 с проверка прокси, вход не понадобился.

**Проверить на сервере** после выкладки: в суточной сводке «Входов в Unity заново»
должно стать 0–1 в сутки, в логах прогонов без постов — строка «вход в Unity не
понадобился», прогон — секунды вместо минут.

Если сессия всё равно будет слетать: проверка живой сессии ещё открывает тяжёлую
страницу «топ бесплатных» (`ValidateSessionForAssetStoreAsync`, на Deck 6 с) — её можно
заменить проверкой на уже открытой странице.

**Побочный эффект проверки 27.09:** профиль `deck__betmansmall` на Deck был разлогинен

### 9. Fab (fab.com) — на ПК и Deck с 1.28.3, на сервере с 1.29.0 (09.10)

**Зачем.** Больше половины постов `unity_assets_1` ведут на Fab, плюс раз в две недели Fab раздаёт
несколько платных ассетов бесплатно («Limited-Time Free»). Всё это — на аккаунт Epic Games.

**Как пользоваться**

- **ПК или Deck:** `./run.sh` / `run.bat` → **F** раз в неделю-две (раздача меняется раз в две недели)
  или когда бот пришлёт сообщение про Fab. Обычно — минута-две и, возможно, одна галочка Cloudflare в
  начале. Пункт **E** — только вход в Epic (F входит и сам).
- **Сервер:** вход в Epic один раз руками (ниже), потом `FAB=on` в `.env` (вопрос в `./deploy.sh`) — после
  каждого прогона Unity сервер сам берёт новые ссылки Fab из каналов. Человека зовёт только за входом,
  галочкой Cloudflare и лицензией Fab, не чаще раза в сутки. Раздачи −100 % — два способа (ниже).
- **Команды на сервере** (между прогонами; `docker compose exec -it unity-assets dotnet UnityAssetsDownloader.dll
  --logs-dir /app/logs --data-dir /app/data --profile server …`): `--fab-login` (вход в Epic), `--fab-server`
  (один ручной прогон серверного этапа — проверить до `FAB=on`), `--fab-giveaway` (раздача по очереди),
  `--fab-recon <ссылка>` (получить ассет руками с записью сети).

**Окно для человека на сервере.** Экрана нет, поэтому окно браузера живёт на виртуальном экране Xvfb, а когда
нужен человек, программа поднимает x11vnc (только `127.0.0.1` внутри контейнера, пароль — файл с правами 600)
и noVNC и пишет боту, как подключиться: `ssh -L 127.0.0.1:6085:127.0.0.1:6085 <сервер>`, затем в браузере
`http://127.0.0.1:6085/vnc.html?autoconnect=true&resize=scale`, пароль — `FAB_VNC_PASSWORD` из `.env` (VNC читает
первые 8 знаков). Порт в `docker-compose.yml` — только `127.0.0.1:${FAB_VNC_PORT:-6085}`. Окно — обычный Chrome
без программы (Cloudflare не верит окну под управлением); **закрывать Ctrl+Shift+W** — оконного менеджера нет, кнопок
у окна нет. Закрыли — программа открывает своё окно на том же профиле и продолжает. Ждёт до 30 минут, потом окно
и доступ закрываются (память).

**Как устроено** (подробности и грабли — «Что важно знать → Fab»):

- `Fab/HumanBrowser.cs` — настоящий Chrome/Edge из системы (Windows: Program Files; Deck: Flatpak
  `com.google.Chrome`, из песочницы VS Code — через `flatpak-spawn --host`; сервер: `/usr/bin/chromium` из
  образа), запущенный как обычная программа со своей папкой `data/profiles/<профиль>/fab/browser`. Управление —
  `Fab/CdpSession.cs`, свой маленький клиент DevTools: только разовые команды, домены не включаются.
  `HandOverToHumanAsync` — отдать браузер человеку; настройки `Display`, `BeforeHumanWindow`, `AfterHumanWindow`
  — виртуальный экран сервера и включение/выключение удалённого доступа вокруг окна человека.
- `Fab/RemoteWindow.cs` — Xvfb (`-displayfd`, свободный экран выбирает сам), x11vnc, websockify + noVNC из
  пакетов Debian. Всё по требованию и гасится после: экран живёт на прогон Fab, доступ — на время просьбы.
  Нет пароля — доступ не открывается вовсе.
- `Fab/FabStore.cs` — страницы Fab. Данные ассета и вход — из вшитых в страницу данных и её кнопок
  (никаких лишних запросов). Cloudflare: 15 с ждём, что пропустит сам, потом — человек в обычном окне. Вход через
  Epic: помнит — сам; нет — человек. Бесплатный ассет (базовая цена 0) — `add-to-library` как у кнопки,
  профессиональная лицензия, если даром, затем перезагрузка и проверка «View in My Library». На сервере
  (`DeferManualAdds`): раздача −100 % не ждёт окна — результат «нужен человек»; сбой сети, 403/429/5xx — «повторим
  в следующий раз», а не вызов человека; окно — только за входом, галочкой и лицензией Fab EULA
  (`CanAskHuman`/`OnHumanAsked` не пускают звать чаще раза в сутки). `ReconAsync`, `TakeByHandAsync`,
  `TakeGiveawayAsync` — человек получает ассет сам, программа проверяет по странице; `ParseGiveawayEnd` — конец
  раздачи из надписи «Until October 20 at 9:59 AM ET» (восточное время США).
- `Fab/FabRun.cs` — прогон Fab. Ручной (`--fab`, `--fab-login`, `--fab-url`): каналы без браузера (первый раз
  вся история, дальше новые — `fab/telegram_state.json`), раздача первой, память `fab/library.txt` и
  `fab/removed.txt`, темп — страница раз в 4 с, отчёт `logs/fab-report-*.json`. Серверный этап
  (`RunFabServerStageAsync`, вызывается в `finally` прогона Unity, ничего не бросает наружу; не запускается после
  падения прогона): см. алгоритм ниже. `--fab-giveaway` — `RunGiveawayWalkAsync`.
- `Fab/FabServerState.cs` — `fab/server_state.json`: когда смотрели раздачу, когда звали человека (и зачем),
  конец раздачи и «о нём уже напомнили».
- `Fab/FabAnnouncer.cs` — только при `FAB=off`: новые ассеты Fab из постов сразу боту (`fab/announced.txt`).
- `Notifications/RunDigest.cs` — Fab в суточной сводке: этапов, сеансов браузера, добавлено, ждут вас, галочки
  Cloudflare, сколько раз и зачем звали человека, строка «Fab ждёт вас с …».
- `tools/har-summary.py` — безопасная сводка файла HAR (хосты, методы, пути, статусы, имена полей, значения только
  из белого списка; куки, заголовки, почта и токены не печатаются). Сам HAR никому не отправлять.

**Надёжность (ревью 09.10, две независимые проверки кода):** замок одного запуска `fab/run.lock` (`FabRunLock`) —
служба и `docker compose exec` не делят браузер и файлы; оборванная команда не оставляет процессов (`ChildReaper` по
SIGHUP/SIGINT/SIGTERM, а остатки после SIGKILL — `RemoteWindow.KillStaleProcesses` при следующем запуске, только на
сервере без экрана); человека, который не пришёл, в этом прогоне больше не зовут (`HumanUnresolved > 0` — отказ) и
цикл по ассетам останавливается; отметка «звали» пишется на диск сразу и не стирается, если просьбу оборвало
исключение (`HumanAsks/HumanResolved/HumanFailedAsks`); окно для человека готовится до сообщения боту
(`EnsureHumanWindow`) — нет пароля или x11vnc не поднялся: не звать, сутки не тратить; Xvfb поднимается лениво, после
решения «есть что делать»; этап Fab идёт до `FinalizeProfileName` (иначе папка профиля создавалась заново под старым
именем); «известные» ассеты раздачи (`needs_manual.txt`) пишутся только после доставки сообщения боту и сбрасываются при
новой раздаче; ассеты, которые не удалось проверить 3 прогона подряд, — в `gave_up.txt` (+сообщение), курсор каналов
из-за них не стоит; запас 30 минут в сутках/двух днях (прогоны «раз в N часов» не должны то проходить, то нет);
`ParseGiveawayEnd` понимает и «Until October 6» без времени, а неразобранный конец раздачи пишет предупреждением;
`NeedsHuman` — только для настоящей раздачи −100 %, прочие отказы Fab — «повторим»; `FAB=on` не гасит объявления бота,
если этап не может работать (нет Xvfb/noVNC). Сводка HAR (`tools/har-summary.py`) переписана по принципу «скрыто, пока
не доказано, что безопасно» (ключи JSON, пути, адреса с логином, коды, почта, токены; битые записи не роняют; файл >150 МБ
не читается).

**Алгоритм серверного этапа (после прогона Unity, `FAB=on`):**

1. Человека звали меньше суток назад и он не пришёл — на Fab не заходим (в логе «ответа не было»).
2. Читаем каналы без браузера: канал впервые для сервера — последние 100 постов (старые ссылки разобраны на ПК),
   потом только новые.
3. Нечего проверять, раздачу смотрели меньше 2 дней назад и напоминание не нужно — браузер не открываем, позицию
   в каналах запоминаем («браузер не открываем»).
4. Иначе: виртуальный экран, браузер, `limited-time-free` (вход, галочка — человеку), раздача первой, потом ссылки
   из каналов. Платные пропускаем; раздача −100 % → `fab/needs_manual.txt` и сообщение боту (один раз) с двумя
   способами; свободные добавляем и проверяем по странице.
5. За 3 дня до конца раздачи — один раз проверяем, что осталось неполученным, и напоминаем боту.
6. Позицию в каналах двигаем, только если все найденные ссылки проверены; итоги — в суточную сводку.

**Раздачи −100 % (выяснено 09.10 по HAR, `--fab-recon`).** Это покупка за 0: `POST /i/cart/items` →
окно оплаты Epic (`payment-website-pci.ol.epicgames.com`, `order-preview`: к оплате 0, `isTotalPriceZero`) →
**капча hCaptcha на `confirm-order`** (антибот Epic «Talon», `captchaToken`) → `POST /i/payment/finalize` → корзина
очищается. Капчу решает только человек, поэтому полностью без человека раздачу не взять. С окна сервера Epic
отклонил 2 решения из 3 (`epic.error.captcha.challenge.failed`), с ПК/Deck — надёжнее. Поэтому два способа:
**1) ПК/Deck, пункт F**; **2) `--fab-giveaway` в окне сервера** — по очереди все ещё не полученные ассеты раздачи
в одном удалённом окне, кнопка, проверка «к оплате 0», капча, Ctrl+Shift+W; подтверждает программа по странице.
Вживую 09.10 получено 2 из 2 (~5 минут на оба + галочка Cloudflare в начале).

**Решено:**

- 28.09: галочку «я человек» и капчу программа за человека не проходит — ни кликом, ни обходом; скрывать от
  сайта, что окном управляет программа (`webdriver`), тоже не стали. Человек — в обычном окне. Лицензию Fab EULA и
  покупку за 0 делает человек: деньги и соглашения — его решение.
- ~~28.09: «Fab на сервере — нет»~~ — **пересмотрено 09.10**: проба с адреса сервера показала, что Cloudflare пускает
  браузер под Xvfb; вход и галочку человек проходит в окне сервера. Пройденную проверку и сессию Epic **не
  переносим** с другого компьютера (привязаны к адресу и браузеру) и не пересылаем через бота (чат — не место
  для доступа к аккаунту).
- 09.10: сервер, а не отдельная машина; бот — только звонок и короткие сообщения (ответов словом пока нет — не
  на что отвечать); раздачи — оба способа; сначала `--fab-server` вручную, потом `FAB=on`.

## Как подключать новый Telegram-канал

Канал читается общим кодом и без подготовки: имя в `telegram_sources.txt` (в git: Deck, Windows и сервер читают один
список; сервер ещё и `TELEGRAM_CHANNELS` из `.env`) — и ссылки на Asset Store из постов попадут в очередь. Подготовка
нужна, чтобы (а) в каталоге у ассета были источник, темы и описание из поста и (б) не открывать страницы платных ассетов
из постов-раздач. Так подключали `UnityAssets2D` (09.10, 1.30.0), `UnityAssetsTools` и `UnityAssetsNewFree` (1.31.0).

**Правила** (решение пользователя; не пересматривать без нового запроса):

- в каталог и на аккаунт идёт только то, что можно получить законно: бесплатное, уже имеющееся, платное с рабочим
  промокодом (оплата только при итоге $0). Платные без кода в каталоге не нужны;
- посты-раздачи файла через бота (`t.me/…bot?start=file_…` или `download_…`, «СКАЧАТЬ») — это в основном платные ассеты
  без оплаты. **С 10.10 (запрос пользователя «добавлять всё бесплатное, без разницы какой источник»):** ассет из такого
  поста берётся, если он бесплатен в самом магазине (цена пачкой GraphQL до открытия страницы); платное и ссылки на ботов
  — нет, файлы из бота не скачиваются. Обычная ссылка на бота (подпись, реклама, реферальная) пост не отбрасывает;
- ассет, который магазин не добавил с двух попыток, запоминается (`unaddable_assets.txt`) и не добивается.

**Шаги:**

1. **Разбор.** `python3 tools/channel-survey.py <канал> --samples 2` (~2 мин, только чтение): виды постов по
   месяцам, куда ведут ссылки и какие боты, сколько ассетов бесплатных/платных/уже на аккаунте. Страницы можно
   сохранить (`--pages-dir`) и потом переиспользовать (`--reuse`).
2. **Шаблон.** Посмотреть образцы постов каждого вида, решить, какие брать. Если у канала есть повторяющаяся
   карточка (название, версия, издатель, описание, темы) — добавить её разбор рядом с `ChannelCardParser`
   (образец — карточка «🎮 …» UnityAssets2D). Ссылка часто спрятана за словами: адрес берётся из `href`.
3. **Стенд.** Настоящие страницы канала — в `harness/fixtures/telegram_<канал>_*.html` (`curl -s
   https://t.me/s/<канал> -o …`, старые — `?before=<номер поста>`). Сценарии `CARD` и `CHAN` — образец.
   Ожидания (сколько карточек, раздач, прочих) считать независимым скриптом, а не выводом самого разбора.
4. **Запуск вживую — на сервере** (решение пользователя 10.10: так ближе к рабочим условиям, и лог получается
   компактный). Команды запускает пользователь: `./backfill.sh <канал> --dry-run` (репетиция, ~40 страниц, аккаунт не
   меняется), затем `./backfill.sh <канал>` (вся история, пачками по 30, в фоне; служба на это время останавливается и
   потом возвращается сама). Ход — `./backfill.sh --status`; итог — `logs/last-run-summary.txt` (короткая сводка; она же
   приходит боту файлом): её пользователь присылает ассистенту. Каталог пишется после каждой пачки. На Deck то же самое
   можно запустить командой вида `dotnet run --project UnityAssetsDownloader -- --data-dir "$PWD/data" --logs-dir "$PWD/logs" --headless true --interactive false --sources telegram --tg-channels <канал> --delay-ms 1200 --quiet`
   (папки данных и логов обязательны, иначе создастся пустой профиль), но каталог тогда получится на Deck, а не на сервере.
5. **Сверка.** Повторить `tools/channel-survey.py <канал> --reuse --pages-dir …`: в «бесплатные, которых нет на аккаунте»
   должно остаться только то, что магазин не добавляет (`unaddable_assets.txt`).
6. **Документация и сервер.** Обновить `README.md` и этот файл; коммит делает пользователь. Канал, который нужен всем
   машинам, — строка в `telegram_sources.txt` (коммит, на сервере `git pull`; служба подхватит файл в следующем прогоне);
   только для сервера — `./deploy.sh` → «канал: имя». Заново вводить уже известные каналы не нужно.

**Грабли** (на всё это уже наступали):

- `--source <адрес>` не отключает каналы из `telegram_sources.txt`: прогон продолжится по ним и добавит посторонние
  ассеты. Один ассет вручную: `--no-defaults --source <адрес> --max-visited-assets 1`.
- Полный проход истории (без `--tg-only-new`, так работает `backfill.sh`) откроет страницы платных ассетов из обычных
  карточек — по ~10 с на каждый (у постов-раздач цена проверяется заранее, их платные не открываются). Для проверки
  берите `./backfill.sh <канал> --dry-run` (~40 страниц) или `--tg-only-new` (последние 50 постов канала).
- Разовый прогон нельзя запускать при работающей службе: два браузера на одном аккаунте. `backfill.sh` сам останавливает
  службу и возвращает её; если делаете руками — `docker compose stop unity-assets` до и `start` после.
- В `compose run` без терминала нужен флаг `-T` (в `backfill.sh` он есть), иначе «the input device is not a TTY».
- Программу остановили сигналом (`kill`) — Chrome может остаться и держать профиль: «БРАУЗЕР НЕ ЗАПУСКАЕТСЯ». Закрыть
  Chrome с профилем `data/profiles/<профиль>/chrome`. `pkill -f <шаблон>` убивает и собственную оболочку — искать
  процесс по номеру. Ctrl+C программа переживает штатно.
- Временная папка ассистента (`/tmp/claude-…/scratchpad`) может очиститься посреди работы (перезапуск сессии):
  всё нужное держать в репозитории (`tools/`, `harness/fixtures/`, `logs/`).
- Страница ассета: кнопка «Add to My Assets» рядом со ссылкой на раздел или на полную версию («Free Demo/Sample»);
  главный клик иногда раньше, чем кнопка дорисовалась; плашка «Added» появляется и у ассетов, которые магазин на
  самом деле не добавил (`userEntitlement: null`). Перезагрузка сразу после «Accept» обрывает медленное добавление.

- Бесплатные ассеты в постах-раздачах через бота пропускаются вместе с постом (UnityAssets2D: 4 из 256 таких ассетов

## Что важно знать, прежде чем что-то менять

Это выяснено опытным путём. Легко сломать обратно.

### Вход в Unity

- Адрес входа — `https://assetstore.unity.com/auth/login?redirect_to=%2F`. Прямые
  `login.unity.com/…/sign-in` уводят на регистрацию. Без `redirect_to` вход крутится по кругу.
- Форма двухшаговая: `input#email` → первая `button[type=submit]` «Continue»
  (ниже кнопки Google/Apple/Facebook/SSO — `type=button`) → пароль на следующем шаге.
  Поля заполняются нативным сеттером value, иначе React стирает.
- Первый клик сразу после открытия страницы теряется — ждём `readyState=complete`
  и ещё 1,5 с (`TryAutoLoginStepAsync`).
- **Каждый шаг отправляется один раз.** Раньше форма заполнялась на каждом проходе
  цикла, и неверный пароль слался минутами. Ошибка страницы, капча, второй отказ —
  остановка (`_autoLoginGaveUp`, причина в `_loginProblem`, сообщение боту).
- Вход через Google в браузере под управлением программы не работает и не будет —
  нужен пароль Unity ID.

### Профили

После первого входа профиль переименовывается: `server` → `server__betmansmall`.
`ProfileStore.FindRenamed`: если папки с заданным именем нет, а `имя__*` ровно одна —
берётся она. Без этого `--profile server` на сервере каждый прогон начинал бы с нуля.

### Корзина и оформление заказа по промокоду

- Корзина — `https://assetstore.unity.com/account/cart` (`/cart` — 404).
- Порядок: «Add to Cart» → корзина → убрать всё, кроме этого ассета (по одному: пока
  идёт удаление, остальные кнопки заблокированы; «Saved for Later» не трогать) →
  «Checkout» (`data-test="checkout-button"`) → вход через `api.unity.com/v1/oauth2/authorize`
  → `pay.unity.com/asv2/checkout?orderId=<id>`. Страницу оплаты узнавать по `Uri.Host`,
  а не по подстроке: `pay.unity.com` стоит в параметрах ссылки входа.
- **«Buy Now» на странице ассета не нажимать никогда.** Это Express Purchase: при
  привязанной карте списывает деньги сразу, без шага с промокодом (выяснено по JS магазина).

### Кнопки чужих ассетов на странице

На странице ассета есть блоки «ещё от автора», «похожие», «top free assets». У каждой
карточки своя кнопка «Add to Cart» и свой `data-test="add-to-cart-button"`. Поиск по
всей странице берёт первую подходящую — и она вполне может быть чужой: 19.09 на сервере
так в корзину попал `#267305` вместо `#321010`.

Поэтому кнопка проверяется на принадлежность: от неё поднимаемся вверх, пока не
встретится блок со ссылками на ассеты. Одна ссылка — это карточка одного ассета, и её
номер должен совпасть с нужным. Несколько ссылок — общий блок страницы, кнопка своя.
Так же проверяется «Add to My Assets» (там нужный номер берётся из адреса страницы).

Если своей кнопки нет, а чужие есть — ничего не нажимаем, ассет пропускается с
понятной причиной. Сценарии стенда: `P` (только чужие кнопки) и `Q` (своя кнопка среди
чужих).

### Чтение каналов Telegram

- Страница `t.me/s/<канал>` собирается на сервере Telegram: весь текст постов лежит в
  HTML, выполнять на ней нечего. Поэтому её качает обычный запрос, а не браузер.
- Листать страницу вниз бесполезно: отдаётся около 20 последних постов, более старые
  живут на `?before=<номер самого старого прочитанного>`.
- Ссылку в посте часто прячут за словом («Ссылка: тут»), поэтому к тексту поста
  дописываются адреса всех его ссылок. Без этого ассеты теряются.
- Пустая страница и заглушка провайдера — разные вещи. Настоящую страницу узнаём по
  разметке `tgme_`; если её нет, это ошибка сети с меткой
  `TelegramSourceParser.NetworkFailureMarker`, и программа берёт следующий прокси.
- Через бесплатный прокси долго открывается соединение (4–30 с), а не идёт страница.
  Поэтому проверка прокси и чтение делят один клиент и его соединения, а медленное
  открытие перекрывается запасными соединениями. Не возвращать отдельный клиент для
  чтения с коротким таймаутом — ровно это сломалось 19.09 на сервере.
- Браузерный разбор остался запасным и включается сам. Скриншоты постов без ссылок
  бывают только в нём — при чтении без браузера тексты и так лежат в
  `telegram_posts_raw.log`.
- Проверять правки удобно на настоящих страницах: они сохранены в `harness/fixtures/`,
  сценарий стенда `TH` сверяет быстрый разбор с браузерным. Обновить их:
  `curl -s https://t.me/s/unity_assets_1 -o harness/fixtures/unity_assets_1.html`

### Связь с Telegram Bot API

Путь до `api.telegram.org` подбирается перебором, первый ответивший запоминается в
`data/telegram_bot_route.txt`: путь из прошлого раза → напрямую → каждый из
закреплённых адресов Telegram → прокси, найденный для каналов. Соединение ждём 8
секунд: мёртвый путь должен уступить место следующему, а не съесть таймаут запроса.

Важные тонкости:

- DNS нередко отдаёт адрес, до которого у машины нет маршрута, хотя другие адреса того
  же сервиса отвечают. Проверено с Deck: из пяти адресов отвечает только
  `149.154.167.220`.
- При закреплённом адресе подменяется **только адрес назначения**. Имя в проверке
  сертификата и в заголовке `Host` остаётся `api.telegram.org`, иначе сломается TLS.
- Свой `ConnectCallback` отменяет `ConnectTimeout`, поэтому время соединения
  ограничивается вручную.
- Ответ Telegram с отказом (неверный токен, нет чата) перебор прекращает: путь тут не
  при чём. Перебор идёт только по сетевым ошибкам, поэтому сообщение не удвоится.
- **MTProto-прокси для Bot API бесполезен** — это другой протокол. Годятся только
  SOCKS5/HTTP-прокси и туннели.

Весь этот опыт добыт в соседнем проекте, там же диагностика и грабли:
`/home/deck/Code/AvtorProjects/server/LinuxServerWatcher/docs/telegram-access.md`.

### Страница оплаты pay.unity.com (скриншоты 18.09)

Язык и валюта зависят от аккаунта и страны: видели русскую с долларами, английскую с евро.
Сверху вниз:

1. Две галки: EULA **и** отказ от 14 дней одним текстом (внутри подписи ссылка на
   EULA — кликать саму галку); письма Asset Store. Потом «Pay now».
2. Сводка «Items (1) 18.40€ · Subtotal · Tax · **To pay now** 22.45€» (по-русски
   «Покупки … К оплате»).
3. «Enter Coupon/Credit Code to update your price», поле без говорящих атрибутов,
   «Apply». Поле ищется по подписи рядом. По CSS бывает и блок `.summary-coupon`
   (ошибка `dd.note .error`, отвергнутый код `.coupon-item span.invalid`).
4. **Tax Business use**: по умолчанию «Yes» и требуется «Tax number». Отвечать всегда
   «No» и проверять, что выбор сохранился: перед кодом, перед Apply и перед оплатой.
   Пока «Yes» — налог и итог прочерком, а код получает «Organization address info is
   not complete or correct» — это **не** отказ по коду: «No» и код ещё раз.
5. Payment method: по умолчанию PayPal с «Paypal email». При итоге 0 не мешает
   (PathGrid куплен так).

### Проверка цены — про деньги

- Оплата — только если итог ровно 0, у поля кода нет ошибки, обязательная галка стоит
  и в налоге «No» (`payBlocker` перед шагом 8).
- Сумма берётся **после слова итога** («to pay now», «order total», «к оплате»…),
  слово ищется целиком: «total» есть внутри «Subtotal» — при итоге прочерком раньше
  читался Subtotal. Валюта до или после числа: `$`, `€`, `£`, `₽`, коды.
- Никогда не возвращать поиск подстроки `0.00` — её содержит и `$10.00`.
- Ноль засчитывается, только если рядом нет ошибки: без посчитанного налога страница
  может показать что угодно.

### Какие отказы запоминаются

В `rejected_promocodes.txt` — только явный отказ по коду (expired, invalid…) или
частичная скидка. Непонятная ошибка или код без ответа — не запоминаются. 18.09 четыре
кода ошибочно попали туда из-за ошибки про адрес — файл был очищен.

### После «Pay now»

Магазин уводит на `assetstore.unity.com/orders/<id>/confirm`, страница меняется прямо во
время проверки. `VerifyPromoPurchaseAsync` ждёт до 30 с «Thank You For Your Purchase»,
а покупку подтверждает по «Open in Unity» на странице ассета. После нажатия оплаты
корзина не чистится.

### Telegram

- `t.me/s/<канал>` — около 20 последних постов; старые — `?before=<номер>`.
- Пачки (`--tg-batch-size`, по умолчанию 30): каналы по кругу, по странице с каждого,
  пока не наберётся N ассетов, которых нет в памяти профиля. `TelegramChannelCursor`
  помнит, где остановился каждый канал.
- «Только новые» (`--tg-only-new`, всегда в `--watch`): `telegram_state.json` хранит
  номер последнего поста; курсор получает `StopAtId`. Канал впервые — последние
  `postLimit` (50). Отметка сдвигается, только если каналы дочитаны, прогон не
  остановлен лимитом и это не `--dry-run`.
- Промокод: слово «промокод» в любой форме или promo code/coupon, затем код
  **латиницей** — заглавными или с цифрами («чтобы» кодом больше не считается).
- Каналы: общий список — `telegram_sources.txt` (в git, правится на ПК/Deck и приходит на сервер через `git pull`;
  на сервере его не правим — сломалось бы `git pull`). `TELEGRAM_CHANNELS` в `.env` — только каналы, добавленные
  именно на сервере; программа читает оба списка (с 1.31.0), `--tg-channels` в командной строке перекрывает оба.

### Сервер и Docker

- `--watch`: прогон → пауза `--watch-interval` (от начала прогона) → прогон. Каждый
  прогон — новый `UnityAssetAutomationApp` и заново прочитанные параметры. SIGTERM между
  прогонами — выход с кодом 0; посреди — сохранить память и выйти сразу.
- Нет ни X11, ни Wayland (Docker, SSH) → браузер невидимый сам, в любом режиме.
- Chrome пишет блокировку `SingletonLock` с именем «компьютера»; у нового контейнера
  имя другое, и чужую блокировку Chrome не снимает — `RemoveStaleChromeLock` снимает её,
  а в `docker-compose.yml` постоянный `hostname`. Личный Chrome (пункт B) не трогается.
- `init: true` в compose — убирает зомби-процессы браузера.
- `.env`: значения в двойных кавычках с экранированием `\ " $` — так Compose v5
  передаёт любой пароль буквально (проверено `docker compose config`).
- Проверки выходят с кодом 2 при неудаче (`--check-login-page`, `--check-telegram`,
  `--notify-test`, `--login`) — по нему `deploy.sh` понимает, что шаг не прошёл.

### Fab (fab.com) — выяснено 28.09

- fab.com за Cloudflare (`cf-mitigated: challenge`). `curl` — 403 всегда. Chrome от Puppeteer
  (Chrome for Testing 138 с его ключами) — галочка «Verify you are human». Невидимый Chrome — не
  пропускает вовсе (40 с «Just a moment...»). **Настоящий Chrome 154, запущенный как программа,
  с новой папкой — пропустил сам за 4 с.** Ничего не подменяем: `navigator.webdriver` у него
  `true` (так делает `--remote-debugging-port`). Страницы с пройденной проверкой он открывает, а вот
  саму галочку в таком окне человек не пройдёт — для неё обычное окно (см. ниже).
- **Не делать запросов, которых не делает сама страница.** Прямой `fetch('/i/listings/<id>')`
  из страницы Cloudflare отбил (403 challenge), и следующая страница уже просила галочку.
  Страница сама этот запрос не делает: сайт вшивает ответы своего API в HTML —
  `<script id="js-json-data-prefetched-data">` (он же `window.prefetchedData`), ключи — адреса:
  `/i/users/me` (есть — вошли), `/i/listings/<id>` (лицензии, цены). Их и читаем.
- Лицензии: `licenses[].offerId`, `slug` (`personal`/`professional`), `priceTier.price`,
  `priceTier.discountedPrice`; цена для человека = `discountedPrice ?? price` (так считает сайт).
  Скидка раздачи может лежать отдельно — `/i/listings/prices-infos?offer_ids=…`.
- Добавление — `POST /i/listings/<id>/add-to-library`, тело FormData `offer_id`, заголовки как у
  клиента сайта: `X-Requested-With: XMLHttpRequest`, `X-CsrfToken` = cookie `fab_csrftoken`
  (нет cookie — сайт сначала зовёт `/i/csrf`), `Accept-Language`. Разобрано по скриптам
  `static.fab.com` (мутация `cart.addToLibrary`) и совпадает с известными userscript'ами.
- Владение: кнопка ассета «View in My Library» / «Saved in My Library» (гость и не купивший —
  «Add to My Library», платный — «Add to cart»/«Buy now»). Кнопки чужих карточек на странице —
  значки без текста, по тексту находится только главная.
- **`add-to-library` — только для базовой цены 0.** На скидку 100 % (раздача) Fab отвечает 400
  `{"detail":{"offerId":["Not free."]}}` — это покупка за 0 через оформление заказа. Сама страница
  выбирает лицензию так: при всех бесплатных — по порядку `personal`, `professional`; «Add to My Library»
  показывает, только если `priceTier.price === 0` у выбранной.
- Ответ «добавлено» проверять по странице: перезагрузить и дождаться «View in My Library».
- Первое добавление на аккаунте может потребовать принять Fab EULA (сайт проверяет у себя
  `getConsent("fab_eula")`) — это делает человек.
- Вход: `/social/login/epic/?next=<путь>` → epicgames.com → обратно. Epic помнит — возвращает сам.
- **Гостю** сайт тоже вшивает `/i/users/me` — `{uid: "anonymous", isAnonymous: true, features: []}`.
  Вход — только когда `isAnonymous` не `true`. Принята ли лицензия Fab — `hasAcceptedBuyerTos === "accepted"`.
- **Страницу проверки Cloudflare узнавать не по заголовку**: он на языке браузера («Один момент…» у
  русского Chrome, 28.09 Windows). Новая страница проверки без `#challenge-form`; надёжно —
  `window._cf_chl_opt` и скрипт `/cdn-cgi/challenge-platform/h/…/orchestrate/chl_page/v1?ray=…`.
  Не путать с `/cdn-cgi/challenge-platform/scripts/jsd/main.js` — он есть на обычных страницах.
- Частые пробы с одного адреса Cloudflare запоминает: после часа разведки 28.09 даже
  `limited-time-free` открывался только с галочкой. Не гонять Fab пробами без нужды.
- Flatpak-Chrome видит только свои папки: папка профиля передаётся `--filesystem=<папка>`. Из
  песочницы VS Code `~/.var/app` — другой (пустой) вид, поэтому папка профиля — в `data/`, а не там.
- Проверка «я человек» — только руками человека. Автоклик по галочке Cloudflare при разведке
  отказал сам инструмент (правило безопасности), и это правильная граница: её не обходить.
- **В окне под управлением программы человек галочку не пройдёт** (Windows 28.09): `--remote-debugging-port`
  ставит `navigator.webdriver = true`, Turnstile такому окну не верит и просит снова по кругу. Человеку —
  обычное окно без порта (тот же профиль). Прятать `webdriver` (`--disable-blink-features=AutomationControlled`)
  для Fab не стали сознательно.
- **Сервер (09.10).** Cloudflare с адреса сервера пускает Debian Chromium 153/154 под Xvfb с портом DevTools
  (`webdriver=true`) так же, как Chrome на Deck: «Limited-Time Free» за 10 с. Позже галочку просит на заходах через
  ~30+ минут после последней пройденной проверки (похоже на срок жизни пропуска) и один раз в начале сеанса;
  внутри сеанса — не просит. Пропуск и сессию на другой компьютер не переносим.
- **Окно на сервере.** Без оконного менеджера у Chrome нет кнопок окна — закрывать Ctrl+Shift+W. Туннель только с
  `127.0.0.1` (с `localhost` — «Connection refused»). noVNC без пароля не открываем.
- **Покупка за 0 (HAR 09.10).** `POST /i/cart/items` (multipart `listingLicense`) → страница оплаты
  `fab.com/payment/web/purchase?…offers=…` → Epic: `GET /v2/purchase/initialize`, `POST /v2/purchase/order-preview`
  (`orderPrice.amount: 0`, `paymentAmount.amount: 0`, `isDiscountToFree`, `isTotalPriceZero`), Talon
  (`/v1/init`, `/v1/init/execute`, hCaptcha: `getcaptcha`/`checkcaptcha`), `POST /v2/purchase/confirm-order` с
  `captchaToken` (400 `epic.error.captcha.challenge.failed`, если капчу не приняли), затем `POST /i/payment/finalize`
  и `POST /i/cart/clear`; владение — `/i/users/me/listings-states/<uid>` (`acquired`). Автоматизировать это без
  решения капчи нельзя.
- **Сводка HAR.** `tools/har-summary.py` — только структура запросов; на сервере без UTF-8 терминала нужен
  `PYTHONIOENCODING=utf-8` (в скрипте уже переключено). HAR содержит куки: хранить на сервере с правами 600, удалить.
- Flatpak-Chrome из песочницы VS Code (`flatpak-spawn --host`): сигнал процессу `flatpak-spawn` до
  браузера **не доходит**, Chrome остаётся. Закрывать — `pkill -TERM -f '^/app/\S+ .*--user-data-dir=<папка>( |$)'`
  на хосте. Шаблон обязательно с `^/app/`: без якоря `pkill -f` на хосте видит и процессы песочницы
  и 28.09 убил терминал, в строке которого был тот же путь.

## Как проверять изменения

### Стенд (только на Steam Deck)

```bash
dotnet run --project harness              # все сценарии, ~10 минут
dotnet run --project harness -- G,L,N     # только нужные
```

Ни в магазин, ни в Telegram не ходит. Сценарии: `A–D, F` — выкуп (корзина, чужие
ассеты, истёкший код, частичная скидка), `G, H, L, M, I, J, K` — страница оплаты как
на скриншотах 18.09 (налог, галки, ошибка адреса, подтверждение, непонятная ошибка,
«No» не ставится), `E, N, O` — вход (успех, неверный пароль, код), `IV` — период,
`P` — промокоды, `T, TB, TN` — Telegram (разом, пачки, только новые), `id` — номер ассета,
`SI` — вход, когда страница уходит посреди шага, `BOT` — бот после закрытия лога
(макет Bot API), `DG` — суточная сводка, `FAB` — Fab на макете fab.com (Cloudflare, вход Epic,
раздача, правила добавления), `FABLIVE` — Fab вживую без входа, `HANDOVER` — передача окна
человеку с настоящим браузером (оба только по явному запросу),
`FABN` — сообщения бота о новых ассетах Fab, `RW` — виртуальный экран и удалённое окно сервера (подставные
Xvfb/x11vnc/websockify), `FS` — память этапа сервера (раздача, вызов человека, конец раздачи, `FAB=on`), `FRUN` —
серверный этап целиком на подставном Telegram и без настоящего браузера (когда открывать браузер, позиция в каналах,
напоминание), `CAT` — каталог (GraphQL, метки, файлы, страница,
«My Assets», файл боту; ответ магазина в `harness/fixtures/graphql_products.json`), `PR` — цена ассета из данных страницы
(настоящие страницы в `harness/fixtures/asset_*.html`; обновить:
`curl -sL -A "Mozilla/5.0 Chrome/138.0" <адрес ассета> -o harness/fixtures/asset_paid_<номер>.html`).
`CARD` — разбор карточки канала (настоящие страницы `harness/fixtures/telegram_uas2d_*.html`; всю историю канала сверяет
при `UAD_CHANNEL_PAGES=<папка страниц>`), `CHAN` — чтение канала с карточками обоими способами (в очередь только карточки,
раздачи через бота пропущены, подпись с ботом пост не отбрасывает), `CATSRC` — источники из постов в каталоге (запись,
слияние, файлы, страница в браузере), `ADD` — кнопка «Add to My Assets» / «Add to Cart» (ссылка на раздел или полную версию
рядом, чужие карточки по-прежнему отсеиваются, ожидание плашки «Added»).
Стенд вызывает внутренние методы через reflection: переименовали метод или поле —
поправьте имя в `harness/Program.cs`.
