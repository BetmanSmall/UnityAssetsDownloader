## Что дальше

### 1. Читать Telegram без браузера

**Зачем.** Разбор двух каналов занимает около 35 секунд: программа открывает
`t.me/s/<канал>` в окне браузера, ждёт JavaScript, листает страницу.

**Почему это возможно.** Сервер Telegram отдаёт страницу `t.me/s/<канал>` уже
готовой — весь текст постов лежит в исходном HTML.

**Выигрыш.** Примерно вдвое быстрее, плюс исчезает зависимость от того,
успела ли прогрузиться страница.

**Как делать:**

1. Забирать страницу через `HttpClient`. Прокси там уже работает — см. `TestProxyAsync`
2. Доставать текст из блоков `div.tgme_widget_message_text`: развернуть
   HTML-сущности, собрать `href` всех ссылок
3. Старые посты подгружать параметром `?before=<id>`
4. **Браузерный разбор оставить запасным путём** и переключаться на него
   автоматически, если из HTML не удалось достать ни одного поста

**Риск.** Разбор разметки руками ломается при смене вёрстки Telegram.
Поэтому запасной путь обязателен.

**Как проверять.** Число постов и ссылок должно совпасть с текущим разбором;
промокод должен связаться с тем же ассетом; проверить работу через прокси
и переход на браузер при поломке разметки.

### 2. Довести выкуп по промокоду

Ждём действующий промокод. Проверить шаги 4–8 на `pay.unity.com`:
налоговый вопрос, ввод кода, согласие с EULA, кнопка оплаты.

Защита уже стоит: без нулевой итоговой цены заказ отменяется.

### 3. Один exe для 10+ компьютеров

Собрать самодостаточный `.exe`, чтобы не ставить .NET на каждую машину.
Копируется в сетевую папку, запускается двойным щелчком.

### 4. Мелкое

- Проверка сессии иногда занимает 20 секунд вместо 8. Разобраться, почему
  быстрая проверка не срабатывает
- Первый проход по китайскому архиву (270 ссылок) идёт больше 20 минут.
  После заполнения памяти повторные проходы быстрые, но первый стоит ускорить

## Что важно знать, прежде чем что-то менять

Это выяснено опытным путём. Легко сломать обратно.

### Адрес входа

Прямые адреса `login.unity.com/ru/sign-in` и `/en/sign-in` **не работают** —
Unity перебрасывает с них на страницу регистрации.

Работает `https://assetstore.unity.com/auth/login?redirect_to=%2F`.

Параметр `redirect_to` **обязателен**. Без него после успешного входа Unity
возвращает обратно на страницу входа, та снова начинает вход, и так по кругу.

### Форма входа двухшаговая

Сначала спрашивают email, пароль — только на следующем экране. Заполнять поля
нужно через нативный сеттер значения, иначе React стирает введённое.

### Вход через Google не работает и не будет

Google не пускает вход в браузере под управлением программы. Это его защита,
обходить её не нужно. Рабочий путь — задать Unity ID обычный пароль.

### Проверка цены — про деньги

Программа доводит заказ до оплаты **только если итог ровно ноль**. Ищется
именно строка «Order Total» или «К оплате», а не любое число на странице.

Раньше здесь была опасная ошибка: цена считалась нулевой, если где-то
встречалась подстрока `0.00` — а её содержит и `$10.00`. Не возвращайте
поиск по подстроке.

Есть тест на настоящей странице оформления: `$7.31` и `Shipping $0.00 +
Order Total $10.00` не должны сойти за ноль.

### Корзина и оформление заказа по промокоду

Корзина магазина — `https://assetstore.unity.com/account/cart`. Адрес `/cart`
отдаёт 404 (на нём программа и застревала до версии 1.18.0).

Порядок выкупа: «Add to Cart» → корзина → убрать всё, кроме этого ассета →
«Checkout» → pay.unity.com → ввести код → цена ноль или отказ. При отказе ассет
убирается из корзины, а пара «ассет + код» запоминается в `rejected_promocodes.txt`.

После «Checkout» Unity ведёт через вход: `pay.unity.com/asv2/orders/<id>/checkout`
→ `api.unity.com/v1/oauth2/authorize?redirect_uri=https://pay.unity.com/...`
→ `pay.unity.com/asv2/auth/login_callback` → снова страница заказа. Адрес
`pay.unity.com` стоит в параметрах ссылки входа, поэтому проверять надо сайт
(`Uri.Host`), а не искать подстроку в адресе — на этом 1.18.0 решала, что страница
оплаты уже открыта, когда шёл только вход. Если по дороге открывается
`login.unity.com`, программа вводит email и пароль профиля.

Страница оформления — `pay.unity.com/asv2/checkout?orderId=<id>`. Язык и валюта
зависят от аккаунта и страны: видели русскую с долларами и английскую с евро.
Сверху вниз (по скриншотам 18.09):

1. Две галки. Первая — EULA **и** отказ от 14 дней на возврат одним текстом
   (внутри подписи ссылка на EULA — жать саму галку, не подпись). Вторая — письма
   Asset Store. Затем кнопка «Pay now».
2. Сводка: «Items (1) 18.40€ · Subtotal 18.40€ · Tax 4.05€ · To pay now 22.45€»
   (по-русски «Покупки … К оплате»). Сумму брать **после** слова итога и слово
   искать целиком: «total» есть внутри «Subtotal». Валюта бывает до и после числа.
3. «Enter Coupon/Credit Code to update your price», поле и «Apply».
4. Billing: вопрос **Tax Business use** («Yes» только для юрлиц и ИП с российским
   ИНН), по умолчанию выбрано «Yes» и требуется «Tax number». Отвечать **всегда
   «No»** и проверять, что выбор сохранился. Пока стоит «Yes», налог и итог не
   считаются (итог прочерком), а на код приходит «Organization address info is not
   complete or correct» — это **не** отказ по коду: ставим «No» и применяем код снова.
5. Payment method: по умолчанию PayPal с обязательным «Paypal email». Как страница
   ведёт себя при итоге 0, ещё не видели — нужен рабочий код.

В `rejected_promocodes.txt` попадает только явный отказ по коду (expired, invalid…)
или частичная скидка. Непонятная ошибка или код без ответа не запоминаются.

По CSS у блока купона есть и такая разметка: `.summary-coupon` → `dd.input`,
ошибка в `dd.note .error`, отвергнутый код — `.coupon-item span.invalid`.

**Не нажимать «Buy Now» на странице ассета.** Это Express Purchase: кнопка
появляется, когда к аккаунту привязан способ оплаты, и списывает деньги сразу,
без шага с промокодом. Выяснено по JS-коду магазина.

Удалять из корзины только по одному: пока магазин обрабатывает одно удаление,
остальные кнопки у него заблокированы, и нажатия теряются. Отложенные ассеты
(«Saved for Later», у них кнопка «Move to Cart») не трогаем.

Всё это проверено на макетах страниц, а не на живом магазине: вёрстку корзины
и pay.unity.com брали из JS-кода магазина. Если шаг 2 или 3 падает — в `logs/`
остаются скриншот и HTML-дамп страницы.

### Telegram: старые посты

`t.me/s/<канал>` показывает около 20 последних постов. Листать страницу бесполезно:
более старые лежат по адресу `?before=<номер поста>`. Сколько постов читать с канала,
задаёт `telegram.postLimit` в `config.json` (по умолчанию 50).

### JavaScript внутри C# компилятор не проверяет

Ошибка синтаксиса в строке с JS не мешает сборке — она проявится только
в работе. Один такой случай стоил того, что промокоды не работали вообще.
После правки JS-блоков стоит прогнать их через настоящий браузер.

### Логи должны оставаться читаемыми

Полные тексты постов идут в `telegram_posts_raw.log`, а не в основной лог.
Длинные адреса обрезаются. `run.bat` запускает с `--quiet`. Всё это затем,
чтобы лог помещался в сообщение и его можно было прислать целиком.

### run.bat должен быть с переносами CRLF

Иначе `cmd.exe` спотыкается на метках `goto`. За этим следит `.gitattributes`.

## Как проверять изменения

Быстрые проверки, не трогающие аккаунт:

```
--check-login-page     страница входа Unity: на месте ли поля
--check-telegram       каналы: сколько постов, ссылок, промокодов
--list-profiles        какие профили есть на компьютере
--dry-run              полный проход без изменений аккаунта
```

В меню `run.bat` это пункты **C**, **T**, **P** и **7**.
