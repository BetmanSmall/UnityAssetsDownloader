# UnityAssetsDownloader

Программа сама добавляет бесплатные ассеты Unity на ваш аккаунт.

Она управляет настоящим браузером Chrome: заходит на страницу ассета и нажимает
«Add to My Assets» вместо вас. Ссылки берёт из текстовых списков, со страниц
Asset Store и из Telegram-каналов с раздачами.

- вход в Unity — руками один раз или полностью автоматически;
- несколько аккаунтов на одном компьютере, у каждого своя папка;
- уже добавленные и снятые с продажи ассеты запоминаются и больше не проверяются;
- Telegram работает даже при блокировке — прокси подбирается сам;
- платные ассеты по промокоду выкупаются, **но только при нулевой итоговой цене**.

Написано на **C# (.NET 8)** с использованием **PuppeteerSharp**. Работает на
Windows, Linux и macOS; часть удобств (шифрование входа, раскладка окон) — только Windows.

## 1. Быстрый старт

> Для сервера, который сам следит за Telegram-каналами, есть отдельная установка
> одной командой `./deploy.sh` — см. [раздел 8](#8-сервер-сам-следит-за-каналами).

### 1.1 Скачивание и установка
Склонируйте репозиторий на свой компьютер и перейдите в его папку:

```powershell
git clone https://github.com/BetmanSmall/UnityAssetsDownloader
cd UnityAssetsDownloader
```

Для работы потребуется установленный **.NET SDK 8.0+** (Windows, Linux или macOS).

> При первом запуске скрипт (через фреймворк PuppeteerSharp) автоматически скачает необходимую версию браузера Chromium.

### 1.2 Запуск через меню run.bat
Для удобного управления и запуска без ввода длинных команд в корне проекта есть скрипт `run.bat`:

```powershell
.\run.bat
```

На Linux (в том числе Steam Deck) то же меню запускает `run.sh`:

```bash
./run.sh
```

Отличия от Windows: браузер открывается во весь экран, без деления с консолью.
Если экрана X11 нет, а есть Wayland (рабочий стол Steam Deck, терминал VS Code из
Flatpak), браузер сам запускается на Wayland.
Диспетчера учётных данных нет, поэтому email и пароль Unity берутся из
`config.json` или переменных `UNITY_EMAIL` / `UNITY_PASSWORD`, иначе их спросят
при входе. Если dotnet установлен скриптом `dotnet-install` в `~/.dotnet`,
`run.sh` найдёт его сам.

**Порядок работы:**

1. **Пункт 6** — вход в аккаунт. Откроется окно браузера, войдите по email и паролю
   Unity. Сессия сохранится, и дальше программа будет входить сама.

   > [!WARNING]
   > Вход через Google, Apple и Facebook в этом окне **не сработает**: Google
   > не пускает браузеры под управлением программ. Нужен обычный пароль Unity.
   > Нет пароля — задайте его на https://id.unity.com («Забыли пароль?»).

2. Меню не закрывается после запуска. Выберите источник:

   | Пункт | Откуда берутся ассеты |
   |---|---|
   | **1** | Всё сразу: топ бесплатных, китайский архив, свои списки |
   | **3** | Только китайский архив |
   | **8** | Только Telegram-каналы (там бывают промокоды) |

   Программа спросит лимит новых ассетов за запуск (в первый раз укажите `3`)
   и размер пачки из Telegram — по умолчанию 30. Ассеты из каналов берутся пачками:
   программа собирает 30 новых ассетов, проверяет их в магазине, потом собирает
   следующие 30 из более старых постов — и так, пока не кончатся посты или не
   сработает лимит. `0` — прочитать каналы разом, как раньше (по `telegram.postLimit`).

3. Если что-то пошло не так — пришлите файл `logs\errors.log`.
   Пункт **L** соберёт всю папку `logs` в архив, если понадобится больше подробностей.

**Полезные пункты меню:**

| Пункт | Что делает |
|---|---|
| **C** | Проверить страницу входа Unity. Быстро, ничего не меняет |
| **T** | Проверить Telegram, задать свой прокси |
| **P** | Переключиться на другой аккаунт Unity |
| **7** | Проверочный прогон: показывает, что было бы сделано |

## 2. Что программа делает

Программа управляет настоящим браузером Chrome и делает за вас то, что вы делали
бы руками: заходит на страницу ассета и нажимает «Add to My Assets».

Порядок работы:

1. **Вход.** Загружает сохранённую сессию профиля. Если она протухла — открывает
   страницу входа Unity. Войти можно руками или доверить это программе,
   сохранив пароль в Диспетчере учётных данных Windows.
2. **Сбор ссылок.** Из текстовых файлов, со страниц Asset Store и из Telegram-каналов.
   Для Telegram при необходимости сам подбирается прокси.
3. **Обработка каждого ассета.** Программа определяет его состояние:

   | Состояние | Что делает |
   |---|---|
   | Бесплатный | Добавляет на аккаунт, принимает лицензионное соглашение |
   | Уже на аккаунте | Пропускает и запоминает, чтобы больше не открывать |
   | Удалён из магазина | Пропускает и запоминает |
   | Платный без промокода | Пропускает |
   | Платный с промокодом | Оформляет заказ, но **только если итог стал ровно $0.00** |

4. **Итоги.** Пишет лог, отчёт в JSON и понятную сводку в конце.

> [!IMPORTANT]
> Заказ доводится до оплаты **только при нулевой итоговой стоимости**. Просрочен
> промокод, цена не изменилась или её не удалось прочитать — покупка отменяется,
> корзина очищается. Деньги не списываются.

## 3. Параметры командной строки

Для запуска без меню `run.bat`:

```powershell
dotnet run --project UnityAssetsDownloader/UnityAssetsDownloader.csproj -- --headless false
```

| Параметр | Описание |
|---|---|
| `--login` | Только авторизация и сохранение cookies, без обработки ассетов |
| `--config <path>` | Путь к JSON-конфигу (если не указан, приложение попробует `config.json` в корне рабочего каталога) |
| `--dry-run` | Проверка без нажатия кнопки добавления (без изменений аккаунта) |
| `--headless true/false` | Режим браузера без UI или с UI |
| `--recheck-owned` | Перепроверить ассеты, которые числятся уже добавленными. Обычно не нужно |
| `--split-screen true/false` | Консоль в левой половине экрана, браузер в правой. Включено по умолчанию. Только Windows |
| `--verbose` | Подробные логи |
| `--quiet` | Только важное. Перебивает `verbose` из `config.json`. `run.bat` включает его на обычных запусках |
| `--trace-network` | Сетевые логи (включает verbose) |
| `--sources telegram\|top-free\|all` | Набор источников одним словом: только каналы Telegram; каналы и страница «топ бесплатных»; каналы, «топ бесплатных», китайский архив и расширенные списки. На сервере задаётся переменной `SOURCES` в `.env`. Отдельные флаги источников ниже сильнее этого |
| `--no-defaults` | Не подключать источники по умолчанию. Берутся только те, что заданы явно |
| `--extended-sources` | Добавить расширенный список источников (страницы search + archive URL) к базовым источникам по умолчанию |
| `--log-file <path>` | Путь к файлу лога |
| `--profile <имя>` | Профиль аккаунта Unity. По умолчанию — профиль по умолчанию из `data/profiles.json`, а если его нет — имя пользователя операционной системы |
| `--list-profiles` | Показать профили на этом компьютере и выйти |
| `--set-default-profile <имя>` | Сделать профиль основным на этом компьютере |
| `--save-password true/false` | `true` — сохранить логин и пароль в Диспетчер учётных данных Windows, `false` — удалить сохранённый. Без параметра программа спросит один раз |
| `--interactive true/false` | Спрашивать ли про вход в консоли. По умолчанию включено, когда программа запущена из живого окна |
| `--sign-in-url <url>` | Точка входа. По умолчанию `https://assetstore.unity.com/auth/login` |
| `--tg-proxy <url>` | Прокси **только** для Telegram, например `socks5://127.0.0.1:1080`. Unity при этом ходит напрямую |
| `--tg-auto-proxy true/false` | Искать ли рабочий прокси самому, когда Telegram не открылся. Включено по умолчанию |
| `--watch` | Режим сервера: прогон, пауза `--watch-interval`, снова прогон. Невидимый браузер, только новые посты, без вопросов в консоли |
| `--watch-interval <период>` | Период между прогонами: `30m`, `6h`, `1d`. По умолчанию `24h` (`server.interval` в `config.json`) |
| `--tg-only-new` | Читать в каналах только посты, появившиеся после прошлого прогона (`telegram.onlyNew`) |
| `--notify-bot-token <токен>` | Telegram-бот для сообщений (или `TELEGRAM_BOT_TOKEN`, `notify.telegramBotToken`) |
| `--notify-chat-id <id>` | Куда писать. Можно не задавать: напишите боту сообщение, и он запомнит чат (`TELEGRAM_CHAT_ID`) |
| `--notify-test` | Отправить боту проверочное сообщение и выйти |
| `--tg-batch-size <N>` | Сколько новых ассетов собирать из Telegram за одну пачку, прежде чем проверять их в магазине. По умолчанию 30 (`telegram.batchSize` в `config.json`). `0` — читать каналы разом по `telegram.postLimit` |
| `--tg-proxy-list <url\|файл>` | Откуда брать список. По умолчанию — [hookzof/socks5_list](https://github.com/hookzof/socks5_list) |
| `--check-telegram` | Открыть каналы, показать что нашлось, и выйти. Вход в Unity не нужен |
| `--check-login-page` | Открыть страницу входа, проверить поля и выйти. Ничего не нажимает и не меняет |
| `--use-system-chrome-profile` | Открывать ваш обычный Chrome со всеми закладками и входами. Chrome должен быть полностью закрыт |
| `--chrome-user-data-dir <path>` | Явная папка профиля браузера |
| `--logs-dir <path>` | Папка для всех логов, отчётов и скриншотов. По умолчанию — `logs` рядом с exe |
| `--data-dir <path>` | Папка для cookies и состояния сессии. По умолчанию — `data` рядом с exe |
| `--unity-email <email>` | Email для автовхода |
| `--unity-password <password>` | Пароль для автовхода |
| `--delay-ms <int>` | Пауза между обработкой ассетов (мс), по умолчанию 700 |
| `--nav-timeout-ms <int>` | Таймаут навигации (мс), по умолчанию 120000 |
| `--auth-timeout-ms <int>` | Таймаут ожидания авторизации (мс), по умолчанию 300000 |
| `--asset-ui-timeout-ms <int>` | Сколько ждать загрузки элементов на странице ассета (`Add to My Assets` / `Open in Unity` / `Sign in` / `Buy`), по умолчанию 30000 |
| `--max-add-attempts <int>` | Лимит **фактически добавленных** ассетов. Уже имеющиеся на аккаунте (`AlreadyOwned`) и пропущенные платные не считаются. В `--dry-run` считаются `WouldAddInDryRun` |
| `--max-visited-assets <int>` | Лимит по количеству посещённых страниц ассетов (защитный стоп при нестабильной детекции) |
| `--source <url>` | Явный источник ссылок на ассеты (можно указать несколько раз). Если указан хотя бы один `--source`, используются только эти источники |
| `--extra-source-file <path>` | Дополнительный файл со списком URL (по одному на строку). Можно указывать несколько раз; добавляется к базовым источникам или к `--source` |
| `--tg-channels <a,b,c>` | Telegram-каналы через запятую. Если не указан, каналы берутся из `config.json`, а затем из `telegram_sources.txt` |

## 5. Настройка: профили, вход, браузер, Telegram

Один компьютер может обслуживать сколько угодно аккаунтов Unity. Каждый аккаунт —
это **профиль** со своей папкой и своей сессией.

- Имя профиля складывается из **имени пользователя компьютера и аккаунта Unity**:
  `VR1-PC__ivan.petrov`. Так на одной учётке Windows уживаются несколько
  аккаунтов Unity — у каждого своя папка и своя сессия.
- Первый запуск идёт под коротким именем (`VR1-PC`), потому что аккаунт ещё
  неизвестен. После входа программа узнаёт его и переименовывает профиль сама.
  Переезжает всё: и сессия, и папка браузера.
- Если профиль для этого аккаунта уже существует — ничего не двигается,
  следующий запуск просто пойдёт под ним. Чужие данные не затираются.
- В компьютерном классе, где каждый ученик входит в Windows под собой,
  всё это происходит само, настраивать нечего.
- Второй аккаунт на том же компьютере: `--profile <имя>` или пункт **P** в `run.bat`.
- Список профилей: `--list-profiles`.

### Где лежит вход

| Что | Где хранится | Кто может прочитать |
|---|---|---|
| Сессия (cookies) | `data/profiles/<имя>/session.dat` | На Windows файл зашифрован DPAPI под учётку пользователя. На Linux и macOS — права `600` |
| Логин и пароль | Диспетчер учётных данных Windows, запись `UnityAssetsDownloader:<профиль>` | Только тот пользователь Windows, который его сохранил |

Посмотреть и удалить сохранённый пароль руками:

```
control /name Microsoft.CredentialManager
```

Или командой программы:

```
--save-password false
```

### Почему адрес входа именно такой

Прямой адрес `https://login.unity.com/ru/sign-in` **не работает**: Unity перебрасывает
с него на страницу регистрации. То же самое с `/en/sign-in`. Проверено запуском.

Работает точка входа Asset Store — `https://assetstore.unity.com/auth/login`.
Она сама перебрасывает на форму входа Unity вместе со служебными параметрами,
без которых Unity считает переход посторонним.

Проверить это на своём компьютере: пункт **C** в `run.bat` или

```
--check-login-page
```

Форма входа Unity состоит из двух шагов: сначала спрашивают email, и только на
следующем экране — пароль. Программа это учитывает.

### Почему повторные запуски быстрые

Программа ведёт в профиле три списка и не повторяет уже сделанную работу:

| Файл | Что в нём | Экономия на каждом |
|---|---|---|
| `owned_assets.txt` | Уже добавленные на аккаунт | ~4 секунды |
| `deprecated_assets.txt` | Удалённые издателем из магазина | ~60 секунд |
| `rejected_promocodes.txt` | Промокоды, которые магазин уже не принял | ~40 секунд |

Удалённый ассет обходится особенно дорого: кнопки добавления на его странице нет,
и без этой памяти программа полторы минуты ждёт то, чего не будет. В китайском
архиве на 247 ссылок таких набирается много.

Если списки стали неверными (например, вы разбирались с аккаунтом вручную) — удалите
эти файлы или запустите с `--recheck-owned`, и всё проверится заново.

### Экран пополам: логи слева, браузер справа

По умолчанию программа сама расставляет окна: консоль с логами занимает левую
половину экрана, браузер — правую. Видно и то, что происходит на сайте, и что
пишет программа, без переключения окон.

Работает на Windows. Панель задачи учитывается, окна под неё не залезают.
Выключить: `--split-screen false` или `"splitScreen": false` в `config.json`.

На Linux и macOS размер экрана не определяется, браузер открывается во весь экран
как раньше.

### Какой браузер открывается

По умолчанию программа открывает Chrome со **своей папкой профиля**:
`data/profiles/<имя>/chrome`. Это не режим инкогнито — вход в Unity запоминается
между запусками, и ваш личный Chrome при этом не трогается.

Хотите открывать свой обычный Chrome, где вы уже вошли в Google — пункт **B**
в `run.bat` или ключ `--use-system-chrome-profile`. Перед запуском нужно закрыть
**все** окна Chrome, включая значок у часов: Chrome не отдаёт свою папку двум
программам сразу. Если забыть — программа скажет об этом прямо.

### Telegram заблокирован — что делать

Если в логе `net::ERR_CONNECTION_TIMED_OUT` на `t.me`, значит Telegram блокирует
провайдер. Соединение не устанавливается ещё до обмена данными.

**Смена протокола тут не поможет** — ни WebSocket, ни другие таймауты. Блокировка
стоит на маршруте до серверов Telegram, а не в способе подключения.

Помогает одно из двух:

**Настраивать ничего не нужно.** Программа делает так:

1. Если прокси задан явно — берёт его
2. Иначе одним быстрым запросом проверяет прокси из прошлого запуска
3. Если такого нет — так же быстро проверяет, открыт ли Telegram напрямую
4. Не открыт — подбирает из списка сразу **несколько** рабочих адресов
5. Пробует их по очереди, пока посты не прочитаются

Сработавший адрес запоминается, поэтому следующий запуск начинается сразу с него.

Все проверки идут одним HTTP-запросом с таймаутом 8 секунд, а не попытками
браузера по 20 секунд каждая. На заблокированной сети это экономит около двух
минут на каждом запуске.

**Сами каналы тоже читаются без браузера.** Страница `t.me/s/<канал>` приходит уже
готовой: весь текст постов лежит в HTML, выполнять на ней нечего. Программа качает её
обычным запросом — 100 постов из двух каналов читаются за 3 секунды вместо полутора
минут браузером, и второй Chrome для Telegram не нужен совсем. Если страница не
пришла или вёрстка Telegram изменилась, программа сама открывает канал браузером,
как раньше.

| Что можно поменять | Как |
|---|---|
| Свой прокси | `--tg-proxy socks5://127.0.0.1:1080` или пункт **T** |
| Запретить подбор, только напрямую | `--tg-auto-proxy false` или пункт **T**, ответ `N` |
| VPN на весь компьютер | Через него пойдёт и Unity тоже — медленнее |

### Как работает автоподбор

Программа скачивает открытый список SOCKS5-прокси
([hookzof/socks5_list](https://github.com/hookzof/socks5_list), обновляется ежедневно),
проверяет адреса пачками по 25 штук и берёт первый, через который открывается
страница канала. Найденный адрес запоминается в `data/profiles/<имя>/telegram_proxy.txt`
и в следующий раз проверяется первым.

Проверено на живом списке: из 253 адресов с Telegram работали 85, рабочий нашёлся
в первой же пачке. Первый запуск занимает 1–3 минуты, следующие — секунды.

> [!IMPORTANT]
> Через прокси проходят **только открытые страницы каналов Telegram**.
> Вход в Unity, cookies и пароли идут напрямую и через чужой сервер не проходят
> никогда: каналы читает отдельный HTTP-клиент, а Unity — браузер программы.
>
> Прокси из списка — чужие машины. Для чтения открытых каналов это приемлемо,
> для чего-то личного такие адреса использовать не стоит.

Проверить, не трогая аккаунт:

```
--check-telegram
```

Покажет, сколько постов прочитано, сколько ссылок и промокодов найдено.

Остальные источники (пункты 1–5 в меню) работают и без Telegram.

### Вход через Google, Apple, Facebook — не работает

Google намеренно не пускает вход в браузере, которым управляет программа. Это его
защита от автоматизации, и обойти её нельзя. То же самое у Apple и Facebook.

Рабочий путь — задать своему Unity ID обычный пароль:

1. Откройте https://id.unity.com в обычном браузере и войдите через Google
2. В настройках безопасности задайте пароль. Если пункта нет — выйдите и
   воспользуйтесь ссылкой «Забыли пароль?», Unity пришлёт письмо на тот же адрес
3. Дальше входите в программе по email и паролю — этот путь проверен и работает

Аккаунт остаётся тем же самым, просто у него появляется второй способ входа.

### Вход руками или автоматически

При первом входе программа спросит:

- ввести email и пароль — дальше она входит сама, окно браузера можно не трогать;
- нажать Enter — откроется браузер, вы входите руками. Этот путь нужен, если вход
  идёт через Google, Apple или Facebook, где пароля Unity просто нет.

Сессия сохраняется в обоих случаях, поэтому следующий запуск входа уже не требует.

## 6. Где лежат файлы после запуска

По умолчанию каталоги создаются рядом с исполняемым приложением
(`UnityAssetsDownloader/bin/Debug/net8.0/`). `run.bat` перенаправляет их в корень
проекта через `--logs-dir` и `--data-dir`, чтобы логи было проще найти и отправить.

Данные — по профилю (аккаунту Unity) в `data/profiles/<профиль>/`:

- `session.dat` — сессия Unity (на Windows зашифрована DPAPI, на Linux — права `600`);
- `chrome/` — папка браузера профиля: вход запоминается между запусками;
- `owned_assets.txt`, `deprecated_assets.txt` — уже добавленные и удалённые из магазина ассеты;
- `rejected_promocodes.txt` — промокоды, которые магазин явно отверг (истекли);
- `telegram_state.json` — номер последнего прочитанного поста каждого канала (режим «только новые»);
- `telegram_proxy.txt` — последний прокси, через который открылся Telegram.

Общие файлы: `data/profiles.json` — список профилей, `data/telegram_bot_chat.txt` — куда
пишет бот, `data/telegram_bot_route.txt` — каким путём бот дозвонился до Telegram
(напрямую, по закреплённому адресу или через прокси). Любой из этих файлов можно
удалить — программа просто узнает всё заново.

Логи — в `logs/`:

- `errors.log` — все предупреждения, ошибки и падения всех запусков (его и присылать);
- `run-log-*.log` — полный лог одного запуска, `run-report-*.json` — итог по каждому ассету;
- `telegram_posts_raw.log` — тексты всех разобранных постов (дописывается);
- `telegram_promocodes.log`, `telegram_git_links.log` — найденные промокоды и git-ссылки;
- `*.png`, `*.html` — скриншоты и страницы при ошибках; `autologin-*.png` — шаги автовхода,
  `promo_*` — шаги выкупа по промокоду.

Пример статусов в отчёте:

| Статус | Что означает |
|---|---|
| `Added` | Добавлено на аккаунт |
| `AlreadyOwned` | Уже было на аккаунте |
| `PaidSkipped` | Платный без промокода, пропущен |
| `WouldAddInDryRun` | Добавился бы, но это был проверочный запуск |
| `PromoNotApplied` | Промокод не сработал — раздача кончилась. Покупка отменена |
| `Deprecated` | Издатель удалил ассет из магазина. Добавить нельзя |
| `UnknownAfterClick` | Непонятный результат после нажатия |
| `Failed` | Ошибка |

### Про покупку по промокоду

Как это идёт: «Add to Cart» → в корзине остаётся только этот ассет (остальные убираются,
отложенные «на потом» не трогаются) → «Checkout» → на `pay.unity.com` в вопросе
«Tax Business use» ставится «No» → вводится код → ставятся галки → оплата.

Программа нажимает оплату **только если итог стал ровно нулём** — по строке итога
(«To pay now», «К оплате», «Order Total»), а не по любому числу на странице, и только
если у поля кода нет ошибки, галки стоят и в налоговом вопросе выбрано «No».

Если промокод просрочен, цена не изменилась или стоимость не читается — заказ
отменяется, ассет убирается из корзины, деньги не списываются. Явно отвергнутый код
(`PromoNotApplied`) запоминается и больше не пробуется; непонятная ошибка (`Failed`) —
не запоминается, код попробуется в следующий раз. «Buy Now» программа не нажимает
никогда: это Express Purchase, он списывает деньги без шага с промокодом.

Дополнительно в отчёт пишется поле `PurchasedOnText` (если найден текст о дате покупки/добавления).

Также в отчёт пишется поле `DetectionSummary` — краткая сводка сигналов детектора (`free/owned/addBtn/openInUnity/...`) для диагностики.

## 7. Запуск на Windows и сбор логов

### Что установить

.NET SDK 8.0+ — https://dotnet.microsoft.com/download
Проверка в PowerShell или cmd:

```powershell
dotnet --version
```

Chrome ставить необязательно: если его нет, PuppeteerSharp сам скачает Chromium
при первом запуске (несколько минут, около 150 МБ).

### Порядок работы

1. Откройте папку проекта в проводнике и запустите `run.bat` двойным щелчком.
   Скрипт сначала соберёт проект и покажет ошибки сборки, если они есть.
2. Пункт **6** — вход в аккаунт. Откроется браузер, войдите вручную.
   Cookies сохранятся в `data\` и будут переиспользоваться.
3. Пункт **8** — Telegram-каналы из `telegram_sources.txt`.
   Скрипт спросит лимит новых ассетов за запуск — начните с `3`.
4. Пункт **9** — диагностика: `--trace-network --dry-run --max-visited-assets 5`.
   Аккаунт не меняется, зато пишется максимум подробностей.
5. Пункт **L** — упаковать папку `logs` в архив `logs-<дата>.zip` в корне проекта.

### Как прислать логи для разбора

Быстрее всего — файл `logs\errors.log`: в нём только предупреждения,
ошибки и падения всех запусков. Если нужен полный контекст — пункт **L** в меню
соберёт всю папку `logs` в один архив.

### Ручной запуск без run.bat

```powershell
dotnet run --project UnityAssetsDownloader\UnityAssetsDownloader.csproj -- ^
  --logs-dir "%CD%\logs" --data-dir "%CD%\data" ^
  --headless false --verbose --no-defaults --max-add-attempts 3
```

## 8. Сервер: сам следит за каналами

На выделенном Linux-сервере программа может работать без присмотра: раз в сутки
(или как настроите) читает Telegram-каналы, берёт **только новые посты** с прошлого
прогона, добавляет бесплатные ассеты, выкупает по промокоду (только при итоге 0)
и пишет вам в Telegram, что сделала.

### Установка: одна команда

```bash
git clone https://github.com/BetmanSmall/UnityAssetsDownloader
cd UnityAssetsDownloader
./deploy.sh
```

`deploy.sh` спрашивает в консоли:

1. email и пароль Unity (пароль не отображается);
2. токен Telegram-бота — проверяет его и просит написать боту `/start`, чтобы узнать, куда писать;
3. каналы — имя, `@имя` или ссылку `t.me/…`;
4. что читать, кроме каналов: только каналы, плюс «топ бесплатных» или ещё китайский архив
   и расширенные списки (пишется в `.env` как `SOURCES`);
5. период (`30m`, `6h`, `1d`), часовой пояс и имя профиля.

Ответы сохраняет в `.env` (права `600`). Если Docker нет — предлагает поставить.
Затем по шагам проверяет, что всё работает (таблица ниже), и запускает службу.
Любой шаг не прошёл — останавливается и объясняет. Повторный `./deploy.sh` — поменять
настройки: Enter оставляет текущее значение.

Нужны `git`, `curl` и права `sudo` (для установки Docker). .NET и Chromium уже в образе.

| Что | Как |
|---|---|
| Логи прогона | `docker compose logs -f` и файлы в `./logs` |
| Собрать логи для разбора | `./collect-logs.sh` — архив в домашней папке, пароли и токен туда не попадают |
| Каналы, источники, период, пароль, бот | `./deploy.sh` ещё раз — и согласиться перезапустить службу |
| Любую настройку без вопросов | Поменять её в `.env` (`SOURCES`, `WATCH_INTERVAL`, `TELEGRAM_CHANNELS`…), затем `docker compose up -d` |
| Остановить | `docker compose down` |
| Обновить | `git pull && ./deploy.sh` |

### Первый запуск по шагам

Эти шаги `deploy.sh` выполняет сам. Если нужно повторить один из них вручную —
вот команды (в папке проекта; `--profile server` — тот же профиль, что у службы):

| # | Команда | Что должно получиться |
|---|---|---|
| 1 | `docker compose build` | `Successfully tagged` / `Built` |
| 2 | `docker compose run --rm unity-assets --profile server --check-login-page` | «ИТОГ: страница входа в порядке» |
| 3 | `docker compose run --rm unity-assets --profile server --check-telegram` | «Telegram доступен, разбор работает». Если заблокирован — прокси подберётся и запомнится |
| 4 | Напишите боту `/start`, затем `docker compose run --rm unity-assets --profile server --notify-test` | Сообщение «👋 Проверка связи» в Telegram. В логе строка «[Бот] Связь с Telegram есть: …» — каким путём получилось |
| 5 | `docker compose run --rm unity-assets --profile server --login` | «ГОТОВО. ВЫ ВОШЛИ В UNITY». Спросит код — введите в консоли или ответьте боту |
| 6 | `docker compose run --rm unity-assets --profile server --sources telegram --tg-only-new --dry-run` | Список ассетов «[Имитация] … был бы добавлен», аккаунт не меняется |
| 7 | `docker compose run --rm unity-assets --profile server --sources telegram --tg-only-new` | Настоящий прогон: «ИТОГИ», сообщение бота, если что-то добавлено |
| 8 | `docker compose up -d` и `docker compose logs -f` | «Следующий прогон: …» |

После шага 7 в `data/profiles/server__<аккаунт>/telegram_state.json` лежат номера
прочитанных постов, и служба начнёт с них. Проверить это можно, повторив шаг 7:
в логе будет «новых постов с прошлого раза нет».

### Что где хранится

В `./data/profiles/<профиль>/`: сессия Unity, память об уже добавленных ассетах и
`telegram_state.json` — номер последнего прочитанного поста в каждом канале.
Удалите этот файл, чтобы следующий прогон снова взял последние посты
(`telegram.postLimit`, по умолчанию 50).

### Вход в Unity на сервере

Экрана на сервере нет, поэтому вход только по email и паролю Unity ID из `.env`.
Программа входит сама и перезаходит, когда сессия протухнет. Если что-то не так,
вход останавливается после первой же неудачи — повторять пароль программа не будет,
чтобы Unity не заблокировала вход — и бот пишет, в чём дело:

- **«Incorrect email or password»** — проверьте пароль, войдя им на id.unity.com;
- **Unity просит код подтверждения** — бот спросит код, пришлите его ответом в течение 10 минут;
- **капча** — войдите один раз на компьютере через `run.bat`/`run.sh` (пункт 6) и
  скопируйте папку `data/profiles/<профиль>` на сервер.

### О чём пишет бот

- что добавлено и что выкуплено по промокоду (пустые прогоны не пишет);
- оплата нажата, но покупка не подтвердилась;
- не получилось войти и почему;
- программа упала.

### Без Docker (systemd)

Нужны .NET 8 и Chromium (`apt install chromium`). Опубликуйте программу в
`/opt/unity-assets-downloader` (`dotnet publish -c Release -o /opt/unity-assets-downloader`),
положите рядом `telegram_sources.txt`, пароль и токен — в `/etc/unity-assets-downloader.env`
(формат как в `.env.example`, права `600`) и включите службу из
`deploy/unity-assets-downloader.service`. Логи: `journalctl -u unity-assets-downloader -f`.

### То же самое вручную

```bash
dotnet run --project UnityAssetsDownloader/UnityAssetsDownloader.csproj -- \
    --watch --watch-interval 24h --sources telegram
```

`--watch` включает невидимый браузер, режим «только новые посты» и отключает вопросы
в консоли. `--tg-only-new` — «только новые посты» без режима сервера.

## 11. Типовые проблемы

### Проблема: не подтверждается авторизация

Что попробовать:

- проверить саму страницу входа: пункт **C** в меню или `--check-login-page`;
- заново пройти вход — пункт **6** в меню;
- увеличить `--auth-timeout-ms`;
- запускать с `--headless false`, чтобы видеть окно браузера.

> [!WARNING]
> Вход через Google, Apple и Facebook в этом окне **не работает** — Google не пускает
> браузеры под управлением программ. Нужен обычный пароль Unity, см. раздел 5.

### Проблема: кнопка добавления не найдена

Чаще всего это не поломка: раздача закончилась и ассет снова стал платным.
Программа так и пишет и идёт дальше.

Если кнопки нет у ассета, который точно бесплатный:

- посмотрите скриншот в `logs/` — там видно, что было на странице;
- увеличьте `--asset-ui-timeout-ms` до `45000`–`60000`, если страницы грузятся медленно;
- запустите с `--verbose`, в подробном логе будут все найденные сигналы страницы.

### Проблема: требуется повторная авторизация во время обработки ассетов

Так бывает, если сессия протухла посреди работы. Программа справляется сама:
предлагает войти (или входит автоматически, если пароль сохранён), обновляет
сессию и продолжает с того же ассета.

В логе шаги входа помечены как `AuthStep: ...` — например `open-sign-in`
или `auth-confirmed`. По ним видно, на чём именно всё встало.

Ошибки вида `Execution context was destroyed` означают, что страница сменилась
во время проверки. Программа повторяет такой ассет сама, вмешиваться не нужно.

### Проблема: много ложных срабатываний free/paid

Сначала запустите проверочный прогон — пункт **7** в меню. Аккаунт при этом
не меняется, зато в отчёте видно, как программа распознала каждый ассет.

Если страницы грузятся медленно, увеличьте `--asset-ui-timeout-ms`
(например до `45000`–`60000`).

## 12. Важные замечания

- Unity меняет вёрстку и правила без предупреждения. Если что-то перестало
  работать — начните с пунктов **C** и **T** в меню: они показывают, что программа
  видит на странице.
- Пароли не храните в командной строке: там они остаются в истории. Для этого
  есть Диспетчер учётных данных Windows (раздел 5), а на сервере — `.env` с правами `600`.
- `config.json`, `.env`, папки `data/` и `logs/` не попадают в git.
